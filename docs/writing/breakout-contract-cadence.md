# 換一種決策節奏，分數還能直接比嗎？

同一個打磚塊，兩個評估分數差了二十幾倍：一邊是 15 局平均 30.9，另一邊是 721.8。乍看之下，這是手寫規則贏過訓練的證據；但把兩份設定並排，它們量的不是同一件事。

## 30.9 和 721.8 各自是什麼？

30.9 是 Dueling Double DQN 的留出測試：250 萬次遊戲操作訓練，15 個沒參與挑選的起點，平均 30.9、中位數 32.0。它本身也是會掉下來的數字——挑選模型時看到的是 51.4，換到沒參與挑選的起點才剩 30.9。

721.8 是手寫像素控制器的評估：同樣 15 個官方起點，平均 721.8、中位數 810。

前者是 contract v2，後者是 contract v3。差別不只在「有沒有訓練」。

| 項目 | contract v2 | contract v3 |
| --- | ---: | ---: |
| frame_skip | 4 | 1 |
| 一局 agent 決策上限 | 27,000 | 108,000 |
| 一局 emulator frame 上限 | 108,000 | 108,000 |
| 評估起點 | 官方 15 個 seeds | 官方 15 個 seeds |

那 15 個 seeds 是 101–105、202–206、303–307，固定清單，讓不同版本從同樣的起點開始。兩份契約的畫面堆疊、由環境負責的 FIRE 也都一樣；sticky action 都是 0.25，意思是 ALE 有四分之一的機率重複上一個動作，不完全照 agent 這次的選擇走。

## frame_skip 改變了什麼？

contract 規定 agent 多久決策一次。v2 的 frame_skip 是 4：模型看一次畫面，遊戲往前推 4 個 emulator frame。v3 是 1：每個 frame 都決策。

一局的 emulator frame 上限兩邊都是 108,000，所以「這局有多長」相同，變的是這段時間裡 agent 被要求做幾次決定：27,000 次對上 108,000 次。

決策變細不是免費的。v2 的一次決策要在 4 個 frame 之間維持有效；v3 把同樣的位移拆成四份，每一份都要重新決定。同一個網路，學到的節奏就不一樣。

對控制器來說，這件事更直接：它每個畫面都要重算一次球的落點，才有辦法在球到之前把球拍推到位。每 4 個 frame 才更新一次，補救永遠晚一步。

## 把 DQN 放進 v3 之後？

同一個家族在 v3 從頭訓練 200 萬次遊戲操作、單一訓練種子，15 局平均 6.93，最高 12，沒有 clear。

落差至少有兩個可能來源。決策頻率變細，模型學到的節奏被拆開；以及 200 萬次操作在 v3 只相當於約 50 萬次 v2 決策的遊戲時間，訓練量本來就比 v2 那顆 250 萬步的模型少。

這次沒有做對等預算的對照，而且 v3 那顆只有一個訓練種子，所以能說的只有「不能直接比較」，不能說「訓練沒有用」。

要比的話，得同一份契約、同一組 seeds、同一種決策密度，訓練預算也要用 emulator frame 對齊，而不是用 agent step 對齊——v3 的 200 萬步只等於 v2 的 50 萬步。

## 那 4.53 對 1.33 呢？

那組數字更早，屬於模型自己負責發球、還沒有 sticky action 的規則。當時也沒有人先看每一局是怎麼結束的：15 局裡有 10 局是撞到時間上限才停，原因不是模型撐得久，而是掉命後沒有按發球。

固定發球規則之後，同一個系列量到的是 9.00 對 1.73。

數字本身沒有錯，錯的是把它們排在一起排名；同樣的錯，也會發生在 30.9 和 721.8 上。
