# Day 18 evidence

Day 18 compares vanilla DQN and Double DQN with the same Day 16 vectorized
training backend. The manifest is the source of truth for which stage artifacts
completed, which checkpoint was evaluated, and which runs are eligible for
aggregation.

## Reproduction

Run the one-seed pilot first. It performs the 100K screening and extends the
same paired seed to the 250K pilot:

```powershell
conda run --name breakout-rl-engineering python -m scripts.training.run_day18_comparison --stage pilot
```

After the pilot training, evaluation, and fixed-probe diagnostics pass, run
the three-seed main comparison sequentially:

```powershell
conda run --name breakout-rl-engineering python -m scripts.training.run_day18_comparison --stage main --resume
```

The runner uses `configs/eval/breakout_contract_v2.json`, requests the same
NVIDIA CUDA device for both algorithms, and retains the Day 16 N=2 GPU Replay
and float32 settings. A resumed stage records that replay storage is rebuilt
and warmed for `learning_starts`; model, target, optimizer, counters, RNG, and
checkpoint provenance are restored.

Generate the report and all evidence-bearing figures from the manifest:

```powershell
conda run --name breakout-rl-engineering python -m scripts.analysis.generate_day18_comparison_report --require-formal
conda run --name breakout-rl-engineering python -m scripts.analysis.export_day18_evidence --require-formal
conda run --name breakout-rl-engineering python -m scripts.visualization.visualize_day18_comparison --manifest assets/day18/evidence-manifest.json
```

The two primary plots are `dqn-vs-double-eval.png` and
`dqn-vs-double-training.png`. They retain training-seed points/curves and use
actual environment transitions on the x-axis. The additional
`paired-seed-comparison.png`, `q-probe-comparison.png`, and
`runtime-comparison.png` plots answer separate questions and are generated by
the same command. `staged-comparison-flow.mmd` is the verified source for the
rendered stage/gate diagram.

The report excludes any run whose summary is incomplete, whose transition
count does not equal the stage target, or whose Contract v2 provenance is
missing. CPU-only runs are useful for unit tests and smoke checks but cannot
become formal Day 18 model-quality evidence.

`evidence-manifest.json` points at compact artifacts under `evidence-runs/` and
`evidence-q/`. The compact metrics files retain real episode-completion and
diagnostic rows used by the figures; the full local checkpoints remain in the
ignored `runs/` tree and their hashes remain in the comparison/evaluation
provenance.
